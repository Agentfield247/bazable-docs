# bazable gen ui

Generates a form component from an endpoint's request schema.  
By default, produces a **zero‑dependency, standalone HTML file** with embedded CSS and JavaScript.  
You can also use `--ai` to let an AI model generate the UI for any framework.

## Usage
-o, --output <dir> : Output directory (default ./generated-ui)

--framework <name> : Target framework (html or react-tailwind, default html)

--ai : Use AI to generate the UI (requires a configured AI key)

## What it generates
Vanilla HTML (default): A self‑contained .html file with a dark/light theme toggle, semantic form inputs, and native fetch logic. The form handles all fields from the request schema: text inputs, number inputs, and checkboxes. No build tools or dependencies required.

React + Tailwind (with --framework react-tailwind): A .tsx React component using Tailwind CSS classes and state management. If AI is enabled, the component will be fully generated by the AI.

AI‑powered (with --ai): Sends the endpoint schema to your configured AI model (OpenAI, Groq, etc.) and returns production‑ready code for the chosen framework. Falls back to the vanilla HTML generator if no AI key is configured or the AI call fails.

## Prerequisites
The endpoint must have a request schema in your bazable.config.json (run bazable extract -r first).

For AI generation, an AI key must be configured via bazable config --set-ai-key.

## Options
- -o, --output <dir> : Output directory (default ./generated-ui)

## Example
Generate a vanilla HTML form:
```bash
bazable gen ui POST https://api.example.com/v1/settlements

Generate a React + Tailwind form using AI:
```bash
bazable gen ui POST https://api.example.com/v1/settlements --ai --framework react-tailwind

Save the output to a custom folder:
```bash
bazable gen ui POST https://api.example.com/v1/settlements -o ./my-forms
